# VelaFit 无屏夜间开发与验收记录（2026-09-13）

## 1. 结论

本轮建立了可重复构建的 `velafit_headless` 配置，并在 ESP32-P4X
Function EV Board V1.8（ESP32-P4 rev v3.2）实板完成烧录、启动和无屏回归。
当前固件适合继续开发算法、摄像头、PPA、C6 控制链路及离屏 UI，但还不是
“端云协同边缘智能运动体态教练”的完整演示固件。

最关键的事实是：当前姿态后端仍是明确标记的 **SIMULATION**，并未对摄像头
图像运行神经网络。SC2336 已能稳定采集 packed Bayer RAW10，但“RAW10 -> ISP/
去马赛克 -> RGB 192x192 -> MoveNet -> 17 关键点”尚未接通。不得把模拟关键点
测试或管线完成日志作为真实 AI 推理证据。

## 2. 本轮已完成

- 新增无屏组合配置：CSI、PPA、PSRAM、C6 Hosted、网络协议栈、VelaFit
  模拟后端和 tmpfs；关闭 DSI、触摸、音频和 MicroSD 自动挂载。
- 修复 ESP32-P4 PPA 首次调用时的递归互斥锁死锁；修复后管线可完成。
- 修复 One Euro Filter 把位置滤波器同时当作导数滤波器使用造成的状态污染。
- 修复平板支撑以时间戳 0 作为“未初始化”哨兵造成的首次计时丢失。
- 修复摄像头预处理在 8 KiB 应用栈上分配两个约 75 KiB 数组的问题，改为堆
  工作区，并将 PPA scale/rotate/CSC 工作区分离。
- 修复开合跳、俯卧撑和平板支撑测试序列与断言；俯卧撑浅幅样本实测肘角约
  121.57 度。
- 去除“零权重卷积 + 固定关键点”的伪推理路径。模拟后端和无后端现在均有
  明确运行时标识；无后端返回 `-ENOSYS`。
- 无音频配置不再打开扬声器设备，只打印 `[Emulated]` 提示。
- `/dev/fb0` 不存在时不再报告 framebuffer 成功，统一报告
  `DISPLAY NOT VERIFIED`。
- 板级启动自动挂载 `/tmp` tmpfs；离屏 320x240 RGB565 仪表盘/骨架可导出
  230415 字节 PPM。
- 增加 libc 浮点格式支持，串口角度、时间、评分等数值不再显示 `*float*`。
- 将 P4 的 MMCSD 多块传输上限设为 128，修复默认配置的编译约束错误。

## 4. 9 月 20 日前优先级

### P0：演示闭环阻断项

1. **真实姿态推理**：接入已选定且许可证兼容的 MoveNet SinglePose Lightning
   TFLite 模型；验证模型解析、算子注册、PSRAM tensor arena、单帧输出、延迟、
   峰值内存和连续推理稳定性。官方模型输入是 UINT8 `[1,192,192,3]`，输出是
   FLOAT32 `[1,1,17,3]`，不能继续沿用当前 160x160 假设。主机探针已确认当前
   TFLM CAST kernel 不支持该模型需要的 UINT8 输入；还要修复 CAST 并绕开通用
   benchmark 的 64-event profiler 上限，详见模型 manifest。
2. **真实摄像头到模型的数据路径**：实现/接通 RAW10 解包、Bayer 去马赛克或
   ISP、裁剪/letterbox、RGB UINT8 192x192；将实际帧交给推理接口。当前只有
   底层采集测试，还没有 `/dev/video0` 或等价的稳定上层取帧 API。
3. **最小可演示运动闭环**：优先只保证一个动作（建议深蹲）达到“真人画面 ->
   关键点 -> 去抖 -> 计数/错误提示 -> UI”。开合跳、俯卧撑和平板作为增量，
   不要让四动作同时阻塞主闭环。
4. **显示实板 bring-up**：接屏后依次完成 panel reset/backlight、DSI 时序、
   `/dev/fb0`、纯色/色条/方向/撕裂/30 分钟刷新。framebuffer 稳定之后再接 LVGL。
5. **演示所需网络数据面**：在 C6 Wi-Fi 与以太网中至少打通一条 NuttX netdev
   + IPv4 + DHCP + ping + 应用请求。若现场主要用 Wi-Fi，C6 数据面优先于以太网；
   以太网可作为备份链路，但不能只停留在 PHY 探测。启用 RMII 前还必须取消或
   隔离当前 GPIO35 BOOT 按键设备，因为该脚经 R135 同时连接 RMII_TXD1。
6. **端到端降级策略**：网络断开时本地识别、计数和 UI 必须继续；报告进入待
   同步队列，联网后再上传。现场演示不能依赖云服务始终可用。

### P1：显著影响展示完成度

1. **LVGL UI**：建议支持，用于摄像头/骨架区域、动作名称、倒计时/运动计时、
   次数、实时文字纠错、质量颜色和联网状态。LVGL 不是 framebuffer 验收的前置
   条件，应在 `/dev/fb0` 通过后接入。
2. **触摸**：确认 GT911 地址/中断/复位及坐标轴交换、镜像和旋转；只做开始、
   暂停、动作选择等演示必要交互。
3. **30 分钟联合稳定性**：摄像头 + PPA + 推理 + UI + 选定网络同时运行，记录
   帧数、FPS、最大延迟、arena/堆余量、丢帧、DMA 错误和断线重连。
4. **真人动作验收**：白天采集不同距离、身高、衣着、正侧角度和光线样本；为
   深蹲深度、膝内扣等阈值建立真值表，统计漏计/误计而不是只做成功演示。
5. **音频**：白天验证 ES8311、I2S、NS4150、音量和录音；夜间继续保持静音。
   音频提示不是最小闭环阻断项，可在屏幕文字提示稳定后补充。

### P2：有余量再做

- MicroSD 媒体与历史记录、H.264、KWS/ASR/TTS、蓝牙、复杂训练计划。
- 完整云账号体系、数据看板和远程模型更新；比赛前先保证最小真实 API 与离线队列。
- UI 动画、主题和非关键触摸页面。

## 6. 明天接屏需要提供的信息与连接

1. 断电后拍摄屏幕模组背面标签、触摸 FPC 标签、两条 FPC 金手指方向、转接板
   正反面和开发板接口丝印；照片必须能读清型号与 pin-1 标记。
2. 确认使用官方套件随附的 7 英寸 1024x600 屏和对应转接板，记录开发板硬件
   版本 V1.8。不要只根据排线外观猜控制器。
3. 按官方说明确认 15-pin FPC 为反向触点连接；完全断电时插拔并锁紧座子。
4. 同时连接 P4 USB Serial/JTAG（COM3）和稳定供电；大屏测试建议给转接板 USB
   供电。COM4 继续保留给 C6 调试。
5. 上电后先不要运行综合应用：先读触摸 I2C 地址/ID，再做 DSI 纯色和色条，最后
   才跑 framebuffer、触摸坐标和 LVGL。

若实物确为官方随板屏，预期显示链路为 EK79007 + EK73217、触摸为 GT911；仍需
以模组标签、原理图/BOM 和 I2C 实测三者交叉确认。FPC 插反可能导致无显示甚至
电气风险，软件无法替代这一步人工核对。
